# Porting status and remaining work

Reference snapshot: 2026-10-18. Audience: contributors and release reviewers deciding what is implemented, what is intentionally different, and what still needs qualification. This is a bounded, source-backed inventory, **not a claim of a complete OpenSoldat port** or an exhaustive audit of every upstream branch.

## Baseline and evidence rules

The mechanics baseline is OpenSoldat `bf43a43bdd7a069e02c906768807f66e621b2888`, not classic 1.7.1.1 or current upstream HEAD. Content is `opensoldat/base@5b6e5bef23f5c0d58fb1d4d887b9b94ebcf799b4`; pins and the product contract are in [SPEC](../SPEC.md). `reference/opensoldat/` and `reference/base/` are optional pristine upstream submodules registered as pinned gitlinks; the reduced, maintained implementation is in `sim/opensoldat/{sim,shared}`, with required license/author notices retained.

Native client/server and third-party source outside that maintained core remains accessible in the upstream reference, including the unported capabilities cited below. Initialize references [nonrecursively](development.md#pinned-upstream-checkouts-and-dependencies) before using those paths for import, comparison, oracle or native-reference work. Default `bun run check:pins` permits absent references while validating exact staged gitlink pins and initialized references' own HEADs and cleanliness; dirty references fail without modification. `bun scripts/check-pins.ts --require-references` requires both. Prepared-WASM/content application work can skip them, but rebuilding still requires the maintained Pascal source and compiler. This source-layout reduction is not a browser-payload reduction, a new qualification receipt or a deletion of historical evidence.

Use these categories separately:

- **Implemented:** a reachable implementation exists. Source presence, tests existing on disk, or a runnable recipe alone does not prove native/runtime parity.
- **Remaining implementation:** an agreed requirement has no end-to-end product path yet. It remains in scope; this document neither implements nor drops it.
- **Deliberate adaptation / launch non-goal:** a documented policy or platform boundary, not accidentally missing mechanics. Reopening it requires a scope decision.
- **Qualification gap:** the implementation exists, but the required artifact/runtime/scenario evidence is incomplete. Do not relabel it as an unported feature or reuse an older receipt as a new pass.

[The role-divergence ledger](role-divergence-ledger.md) is authoritative for extraction decisions. [PLAN](../PLAN.md) preserves the original gated roadmap and criteria. Gate reports preserve successes, failures and limitations for their recorded binaries; they are not a blanket release approval. [Development](development.md) describes how to produce new evidence.

Current interfaces are simulation ABI/state/render/FX **`0x00010006`** and gameplay **wire7** ([ABI](formats/sim-abi.md), [wire reference](../packages/protocol/README.md)). Default population is **12 total humans plus bots**, with **32 supported slots**. Neither default nor slot count demonstrates qualified server capacity. Node24 hosts authoritative workers; Bun is tooling, not the production server runtime.

## Remaining implementation in the agreed browser scope

### Local custom-map/mod inspection (R-CON-5)

The in-browser local-only `.pms`/`.smod` import and offline viewing path is still missing. `Shell.tsx` selects maps from the imported content index; it has no local file/drop import screen. The [content importer](../packages/content/README.md#reader-boundaries-and-limits) already has PMS v11 readers and bounded ZIP/SMOD parsing, but this is not an end-to-end browser import feature. `readZip` preserves roots and rejects unsafe entries before inflation; base's nested `classic.smod` is inspected, **not mounted as a supported game mod**.

Remaining work includes integrating those boundaries into a local browser workflow, resolving archive mount/dependency policy, and demonstrating offline viewing without uploads. Do not imply that generic ZIP parsing provides full mod, custom-HUD or legacy-map support. Public map hosting remains a separate non-goal.

### Public server browsing/discovery (R-SRV-1)

Quickplay, direct admission and friend-lobby code/link UI are implemented. A filterable public server-list/discovery UI is not. `Shell.tsx` has quickplay/friend/join routes; `platform.ts` exposes region probing, quickplay, lobby creation and lookup, **not a public match-list endpoint**. Quickplay currently allocates public DM matches; friend/practice setup exposes all seven modes.

Distinguish this scope gap from the native ecosystem: pinned `reference/opensoldat/server/LobbyClient.pas` registers native server metadata at `/v0/servers/register`. The browser's application-specific registry is not native lobby registration or original-server interoperability. This evidence does not establish that the pinned native client contains a complete server-browser UI.

## Deliberate mechanics and browser adaptations

Consult the ledger for exact branches and rationales rather than treating these as bugs or undiscovered missing work:

- **Server-role mechanics/input-only authority:** the browser sends controls and bounded intent, not native position/hit claims. Authoritative human owners use the ledgered Dummy/BOT adapter with preserved human trigger/loadout semantics (C02, C05–C09). Native client historical collision/delayed pushes and the extra client fuel decrement are not reproduced (C04, M03/M05).
- **RNG ownership:** original policy is the T1 oracle policy; keyed gameplay/AI streams are a deliberate product alternative. FX has its own RNG and is excluded from save/hash. A keyed run cannot be labeled bit-identical to the original global-RNG gameplay merely because both are deterministic (R01–R04).
- **Presentation-only local behavior:** bink, camera, settings, menus, chat and media are outside gameplay hashing. No claim is made to import every native cursor/camera mutation into authoritative state (C01, B05, ABI6 boundaries).
- **Round scheduling and immutable identity:** native score/time/countdown mechanics remain; the host chooses/loads compatible maps and preserves admission across monotonic epochs. OS clocks, original socket loops, script callbacks and native process map loading are not a second gameplay clock.
- **Explicit policy extensions:** departure rebalancing is broader than native admission-only balancing. Player voting uses admission identities and a frozen electorate, with a global cooldown stronger than the original per-starter cooldown. Browser capabilities replace native command authority.
- **Web platform substitutions:** React/Phaser/Web Audio replace SDL/OpenGL/OpenAL/launcher UI; lossless WebP and lossy Opus are declared content transformations. Voice replaces Steam media transport with opt-in peer WebRTC, not a server-media-authoritative SFU. Full archive/asset provenance remains required.

## Priority order

1. **Bind release evidence to the actual artifact.** Record source/pins, WASM/native/content identities, ABI/wire and exact runtime versions. Requalify changed mechanics and recoverability; retain historical failures and intentional-divergence decisions.
2. **Close online/platform release risks.** Prioritize the current impaired-network/recovery matrix, representative 16-player performance, longer/multi-match soaks, target browsers and configured Internet voice. Do not spend this phase implementing excluded native subsystems.
3. **Finish already-agreed product gaps.** Deliver the local-only custom-map/mod inspection workflow and public server browsing/discovery only with their source/content-safety and acceptance boundaries; do not conflate these with the existing menu/friend lobbies.
4. **Complete release review.** Resolve public-brand permission, production deployment/regions, current visual/audio/content evidence and recorded veteran playtests. Launch decisions must name any approved scope change; they cannot silently waive SPEC requirements.
5. **Reconsider excluded compatibility only explicitly.** Demos, scripts, native RCON/networking, custom HUDs, legacy formats, music and native catalogs each need a separately scoped decision and evidence. Their retained upstream files are comparison material, not dead code to erase during repository cleanup.
