**Zero Safari hash mismatches or posted simulation errors were observed.** Repeated whole-corpus attempts stalled after two combat receipts. A pristine isolated prone fixture passed; fresh pages on reused origins could also stall, whereas fresh-page/fresh-origin collection produced the 45 accepted original receipts. Long-run attempts remained incomplete. This is a **suspected harness/page-lifecycle issue, not an established root cause or a passing result**. WebContent was observed at 0% CPU in process snapshots; a diagnostic sample also showed executing compiled microtasks, so idle snapshots alone do not prove a deadlock. Temporary diagnostic progress showed 29,229,056-byte WASM memory at the measured early ticks, not unbounded memory growth.

Safari WebDriver could not create a session because “Allow remote automation” is disabled; `safaridriver --enable` required authentication. Apple Events JavaScript is likewise disabled. No unavailable diagnostics are claimed as exercised. Temporary progress/request hooks were removed; only owned diagnostic windows/servers were closed. No engine was substituted for Safari, no incomplete receipt was counted, and no simulation code was changed to evade the gap.

## Resource discipline and historical performance

Builds, Docker captures, Node matrices and qualification browsers were serialized. Docker outputs, TMPDIR and HOME stayed on host binds; no Docker objects were pruned. Memory was checked before heavy steps. The Node trace runner now writes each trace row directly to disk instead of retaining a whole large trace in memory. Superseded scratch traces created by this qualification were removed after their comparisons and result/receipt identities were recorded; JSON receipts/results remain.

The earlier save/hash benchmark measured p50 1.313833 ms, p95 1.398375 ms and 173,216 bytes on a superseded artifact. It is **historical, not final-artifact performance evidence**. The ≤1 ms goal was not achieved by that measurement and is not claimed here. This run qualifies correctness rather than inventing a new performance result.
