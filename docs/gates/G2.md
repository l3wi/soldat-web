## Implemented runtime

The production local sandbox mounts SHA-256-verified raw simulation core files and the selected PMS, initializes the actual OpenSoldat WASM, loads the map and joins one original player slot. Inputs use the persistent 12-byte ABI record. `ClientClock` advances exactly 60 fixed ticks per simulated second, caps live catch-up at four ticks, and resets live time/input on visibility changes. The renderer reads original previous/current world skeletons; it never evaluates POA animation or writes a render pose back into simulation memory. The Respawn toolbar action submits `sim_command(currentTick,{kind:"spawn",slot:1})`.

The live sandbox explicitly joins `control:"authoritative"` (original server-owned control with AI disabled), while qualification fixtures retain their declared control role; the legacy 98 movement fixtures default to HUMAN. This distinction is part of the simulation contract, not a silent fixture migration.

ABI `0x00010002` consumers use shared render/FX constants, including authoritative team. Sound kind `0x80000004` maps to the original `Sound.pas` 163-slot sample table, imported WAV objects and Phaser Web Audio voices. Explicit unlock is required; native distance gain and OpenAL-equivalent coordinates are preserved without a second distance attenuation. Reserved/free source channels, play-if-not-playing, loop, stop, volume, pause and resume operations are handled. Unknown presentation kinds remain counted, not interpreted as sound.

Cosmetic camera/local-slot context is supplied before stepping. `fx_step` runs once per gameplay tick. `fx_render_view` is consumed in the native sparks/weather draw-order slot, after soldiers/Things and before scenery L1. Native spark styles retain lifetime/position interpolation, native graphic/frame selection, source-over tint/alpha, scale/rotation and overlapping explosion/smoke layers. Rain/sand/snow use alpha 105. Unsupported cosmetics remain an explicit unavailable state, never a synthetic substitute. Cosmetic sound/particles are not gameplay hashes.

Bullet/Thing visual presentation, weapon-specific appearance/HUD and bots are later-phase scope; this G2 record does not claim those features.

### Rendered-loop determinism methodology

`/?g2&map=Airpirates&run=<identity>` runs every entry in `tests/fixtures/movement/corpus.json` at each display rate. Real installed browser engines execute accelerated deterministic `Phaser.Game.step(frame*1000/rate,1000/rate)` calls. **This is simulated display timing, not a claim of physical 120/144 Hz displays or real-time performance.** Each call invokes the ordinary scene update, accumulator and renderer. Long cases yield to the browser without advancing display time.

Fixture controls enter the same persistent 12-byte submission path as ordinary sampled controls; this is not a second fixture-only simulation loop and does not call sim-host `runFixture`. It is also not a claim that scripted fixture bits were generated through DOM key events. Real keyboard/mouse input is exercised independently by live sandbox capture checks.

The collision map, verified full content set, seed, players, commands and controls are each fixture's actual data. The map **render backdrop remains Airpirates** for the hash sweep, including synthetic collision fixtures. Soldiers use the real fixture's evolving simulation skeletons. All ordinary scene drawing, camera, event drain/audio boundary and cosmetic stepping/rendering remain on. Every tick-zero-through-final gameplay hash is compared on the local evidence server against `build-out/sim/receipts/node/<name>.receipt.json` (the same baseline exported as `<name>.hashes.jsonl`). Zero dropped ticks and actual render counts are required; the final post-render hash is checked too. Cosmetic event bytes are intentionally not compared to Node because local camera/voice/weather presentation context differs.

Full receipts bind exact WASM SHA-256, fixture-byte SHA-256 and effective verified content-set SHA-256. `build-out/client-g2/results.json` is written only after all **98 fixtures × 3 rates × 3 engines = 882** distinct cases are accepted. A navigation, canvas, partial run or synthetic clock-only result cannot produce that completion artifact.

**Status: PENDING USER ACTION. No human feel comparison has been performed or fabricated.** The following recipe is source-backed setup for a real local comparison; the optional native-server bootstrap below has not been exercised as part of this client qualification.

### 1. Prepare the native and browser windows

From the repository root on the interactive macOS desktop:

```sh
sh tools/refclient/build.sh
# The capture build intentionally builds only the native client. For actual play,
# enable the ordinary native server in that same isolated source/build tree:
cmake -S build-out/refclient/source -B build-out/refclient/cmake \
  -DBUILD_SERVER=ON -DBUILD_SCRIPTCORE=OFF -DBUILD_RCON=OFF \
  -DADD_ASSETS=OFF -DCMAKE_BUILD_TYPE=Release \
  -DOPENSSL_ROOT_DIR=/opt/homebrew/opt/openssl@3 \
  -DCMAKE_PREFIX_PATH=/opt/homebrew -DCMAKE_Pascal_FLAGS=-Fl/opt/homebrew/lib
cmake --build build-out/refclient/cmake --target opensoldatserver --parallel 4
ditto reference/base/server build-out/refclient/data
printf 'Arena\nAirpirates\n' > build-out/refclient/data/configs/g2maps.txt
```

Run the native server in its own terminal (do not expose it to the internet):

```sh
env DYLD_LIBRARY_PATH="$PWD/build-out/refclient/cmake/bin:/opt/homebrew/lib" \
  build-out/refclient/cmake/bin/opensoldatserver \
  -fs_portable 0 -fs_localmount 1 \
  -fs_userpath "$PWD/build-out/refclient/data" \
  -fs_basepath "$PWD/build-out/refclient/data" \
  -net_ip 127.0.0.1 -net_lan 1 -net_port 23073 -sv_lobby 0 \
  -sv_gamemode 0 -sv_maxplayers 1 -sv_timelimit 0 \
  -sv_realisticmode 0 -sv_survivalmode 0 -sv_bullettime 0 \
  -sv_bonus_frequency 0 -sv_maplist g2maps.txt -
```

After it reports ready, enter `map Arena` in the **native server terminal**. In another terminal, start the ordinary native client, explicitly disabling the screenshot/gallery entry points:

```sh
env -u REFCLIENT_MAP -u REFCLIENT_GOSTEK -u REFCLIENT_SCREENSHOT \
  DYLD_LIBRARY_PATH="$PWD/build-out/refclient/cmake/bin:/opt/homebrew/lib" \
  build-out/refclient/cmake/bin/opensoldat \
  -fs_portable 0 -fs_localmount 1 \
  -fs_userpath "$PWD/build-out/refclient/data" \
  -fs_basepath "$PWD/build-out/refclient/data" \
  -r_fullscreen 0 -r_screenwidth 1280 -r_screenheight 720 \
  -r_renderwidth 1280 -r_renderheight 720 -r_dithering 0 \
  -r_texturefilter 2 -r_mipmapping 0 -r_smoothedges 1 -r_msaa 0 \
  -snd_volume 100 -cl_player_name G2 -connect 127.0.0.1 23073 -
```

Choose an ordinary human player/weapon if prompted; do not add bots. Start the Vite client using the commands above, open `http://127.0.0.1:5195/` in the chosen browser, restore default controls, choose linear filtering/mipmaps off, select **Arena**, and click **Start sandbox**, then **Enable audio** and focus the canvas. Do not use `capture` or `g2` query parameters for the manual session. Arrange the two windows side by side (or on matched displays); match their canvas aspect and scale. Keep browser zoom at 100%, avoid wheel zoom and keep both views unscoped.

### 2. Repeat the same movement sequence in both windows

Use the same keyboard/mouse, first native then browser; repeat in the reverse order to reduce adaptation bias. Start each group from a recognizable flat ledge or respawn point, matching mouse aim direction. Do not interpret a different randomized spawn as a physics discrepancy.

1. Tap then hold A and D; reverse direction while grounded and airborne.
2. Hold A then add D; repeat D then A, on ground and in air.
3. Tap W versus hold W through landing; compare jump timing/height and repeated-jump behavior.
4. Run into W for sidejump; reverse facing/input for backflip; compare the animation-gated transitions.
5. Use S while running/airborne for crouch and roll, X for prone, then stand/get up; compare low-ceiling collisions and delays.
6. Hold right mouse to empty jets; land, refill, and test short bursts at nearly empty fuel. Compare exhaust placement and sound start/stop.
7. Move across slopes/edges and skim ceilings/corners; compare sticking, sliding and landing response.
8. Sweep the mouse while running/jumping; compare aim offset, camera follow and perceived input-to-visible movement.
9. Use **Respawn** in the browser; use the native death/respawn flow. Compare the resulting spawn state, not the UI delay (the browser button is a direct sandbox command).

For **Airpirates**, return to the browser main menu and select Airpirates; enter `map Airpirates` in the native server terminal and wait for the native map change. Repeat all nine groups, including the map's slopes/platform edges, jet traversals and scenery overlap. The first menu transition must not leave stuck keys or a duplicate canvas.
