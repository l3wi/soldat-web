### Environment prerequisite failure observed

Before the pinned image was available, a throwaway `debian:bookworm-slim` prototype Docker build attempted to install distro FPC 3.2.2 and native dependencies. `apt-get update` failed with exit 100, reporting `At least one invalid signature was encountered` for all three Debian repositories. No apt authentication was disabled. Investigation:

```text
$ docker run --rm alpine:latest df -h /
Filesystem  Size   Used   Available  Use%  Mounted on
overlay     58.4G  56.7G  0          100%  /
```

The Docker VM had insufficient free storage. The temporary prototype Dockerfile was removed; the pinned toolchain image was subsequently completed. The oracle build directs TMPDIR/HOME and all source/CMake/GNS outputs to the host bind mount `build-out/oracle`, rather than installing anything more into the VM.

`tools/oracle/OracleHarness.pas` is a wholly new unit copied to `server/OracleHarness.pas`. Its entire checked-in content is the harness addition, not a hidden mechanics patch. It:

1. Sets FPC `RandSeed` from the fixture **instead of reaching** `Server.ActivateServer:585 Randomize`.
2. Initializes normal Cvars and the original dummy-player ownership arrangement; disables scripts/lobby/log writing/autodemos and bonus spawning; uses non-realistic DM with ordinary gravity/weapon defaults.
3. Calls original `LoadAnimObjects`, PhysFS map lookup/`Map.LoadMap`, `Server.LoadWeapons`, and `CreateSprite`. It uses exact selected map spawn coordinates, not random spawn selection.
4. Increments the three normal tick counters once per tick; applies fresh fixture `TControl` **before** calling original `UpdateFrame`.
5. Sets `NoClientUpdateTime[slot] := 0` before every tick for active fixture soldiers. Original `Sprites.pas:531–534` (controls) and `1178–1185` (jet refill) continue to evaluate their unmodified HUMAN/input-silence conditions. No bot/AI substitution is used.
6. Writes an initial state plus all stage snapshots and a final `tick` snapshot. It never mutates physics during dumping; float bits come from `Move(Single, LongWord, 4)`.

No file in `shared/mechanics` is patched. All arithmetic, integration, collision, pose, control, weapon, jet and RNG-consuming mechanics run as pinned.

## Build/content isolation

The driver extracts exact pinned Git archives, applies the patch in `build-out/oracle/source`, and configures server-only Release CMake with `BUILD_SCRIPTCORE=OFF`, `BUILD_RCON=OFF`, `BUILD_STEAM=OFF`, `ADD_ASSETS=OFF`, and `-dORACLE`. `ENABLE_FAE` is not defined. Upstream GNS is linked, but no transport is initialized, no clients connect, and trace executions have Docker `--network none`.

Upstream GNS FetchContent writes into its source directory, so the build **must remain in the writable copy**. The base archive is built by the original `create_smod.py` in a separate writable base copy. PhysFS mounts the resulting `soldat.smod` at `/`; original animation/skeleton loaders and map parser read it. The original bundled server `weapons.ini` is copied to `runtime/configs` for `Server.LoadWeapons`.
