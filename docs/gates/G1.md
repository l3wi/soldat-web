## Implemented boundary

The sim compiles the original `Game`, `Parts`, `Anims`, `PolyMap`, `MapFile`, `Weapons`, `Cvar`, `Util`, `Sprites`, `Control`, `Bullets` and `Things` with `SERVER` and `SIM`. `SERVER` retains source server-role semantics; `SIM` selects infrastructure and portable RNG imports. Platform units in `sim/opensoldat/sim/` precede original infrastructure in the search path. There are no SDL/Steam/socket/C-object dependencies in the extracted builds.

The production ABI, input/render/event numeric layouts and explicit state schema are documented in [sim-abi](../formats/sim-abi.md). Implemented paths include VFS bytes, original map/animation/PO/weapon loading, exact `CreateSprite` setup, join/leave/team/spawn commands, input order handling, fixed frame/stage ordering, ordered events, real sprite/bullet/Thing views, explicit state save/load/hash and diagnostic traces. `fx_step`/`fx_render_view`, unsupported rules/flags and AI remain explicit errors. One instance owns one initialization/map; reinitialization or a second map load returns unsupported.

The serializer is not a raw memory dump. It retains all mutable primitive fields, including inactive stale particle data and signed zero, through lossless sparse particle/constraint lists. Immutable animation frames are content-bound and rebound on load; the load path rechecks template frame hashes. A source search for `Frames[` and `.Frames :=` found original frame-coordinate writes only in `Anims.LoadFromFile`; runtime movement reads frames. All six original-policy RNG words, tick counters, input history, background state and outgoing snapshot histories are included. Load performs complete nonmutating validation before applying state.

The ledger is [role-divergence-ledger](../role-divergence-ledger.md). Server fuel exhaustion/refill, immediate pushes, idle RNG, environmental damage/death/projectiles and the pinned team-filter anomaly are retained. Client-only cosmetic RNG, camera/SDL acquisition and local bink/recoil branches are not silently enabled. No ledger entry authorizes a server-role T1 movement deviation.

## Portable original RNG proof

The pinned RTL's RNG state is not `RandSeed` alone: it also contains a reseed sentinel and four xoshiro128** words. Native RTL symbols are exported, but WASM symbols are local. The final implementation **does not patch/globalize RTL objects or modify the installed compiler**. `SimRandom` independently implements the [public-domain SplitMix64](https://prng.di.unimi.it/splitmix64.c) and [public-domain xoshiro128**](https://prng.di.unimi.it/xoshiro128starstar.c) algorithms with the pinned FPC reseed, integer-bound and floating-bit mappings. No FPC RTL implementation text was copied.

Only the used portable surface is exposed: `Random(LongInt)`, `Random(Int64)`, `Random: Extended` and unsigned `RandSeed`. An exploratory `Math.RandomRange` boundary exposed native-64/WASM-32 overflow-width differences; no movement call site uses it, and it was removed rather than introducing target-dependent RNG behavior. See ledger R01–R03.
